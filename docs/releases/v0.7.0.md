# Vox 0.7.0: a voice assistant that knows who is speaking, and stays on your machine

0.7.0 turns Vox from a local STT/TTS toolkit into an offline voice runtime: full-duplex conversation with reliable barge-in, speaker identification inside the conversation, opt-in long-term memory per person, and an offline mode you can check.

## Highlights

### Live Talk protocol v2
- Barge-in works in every phase of a turn. Before reply audio starts, the server listens and cancels the turn when you speak. During playback the client detects your voice and sends `cancel`; the bundled web UI does this, and other clients have to do the same.
- Short noises no longer cancel a reply that is still being transcribed or generated: speech has to last 250 ms before it counts as a barge-in.
- The conversation records what was heard, not what was generated: an interrupted reply is cut down to the sentences that were actually played.
- `ready` carries `protocol_version: 2` and a `session_id`; turn-scoped events carry a `turn_id`. The conversation survives a reconnect with the same `session_id` (idle sessions are kept for 30 minutes; `VOX_SESSION_TTL_SECS`).
- Per-turn latency in `turn_metrics`.

### Speaker-aware conversation and per-person memory (experimental)
- Live Talk identifies known speakers while they talk and names them to the model. This needs the `speaker-encoder` model.
- No voiceprint is stored before consent is recorded. In Live Talk, talking never enrolls or adapts a voiceprint: a voice is stored only by the explicit `enroll_speaker` command. In the Listen tab, new voices are enrolled automatically once consent is given.
- Long-term memory is off for every speaker until it is switched on for them (`PUT /v1/speakers/{id}/memory` with `{"enabled": true}`). It lives in the local SQLite speaker database and is recalled at the start of that person's next session.
- When turns fall out of the context window, the conversation's Ollama model distills them into facts while the conversation is idle (`memory_distilled`). `VOX_MEMORY_DISTILL=0` turns this off.
- Forgetting a speaker deletes their memory; `GET /v1/speakers/{id}/export` includes it.
- Speaker REST API under `/v1/speakers`: list, rename, forget, merge, export, consent.

### Offline mode and privacy ledger
- `--offline` (or `VOX_OFFLINE=1`) refuses an Ollama host that is not loopback and refuses all model downloads.
- `GET /v1/privacy/ledger` shows the outbound connections the server process made: destination, purpose, body bytes. It keeps the last 500 connections individually and totals per destination.
- Not covered: the optional `pocket`, `chatterbox` and `qwen3` backends fetch weights through the Hugging Face hub client. They are not in the release binaries.

### Hardened server
- Binds to loopback only; a non-loopback `--host` needs `VOX_ALLOW_REMOTE=1`.
- Cross-origin requests are rejected unless allow-listed (`VOX_ALLOWED_ORIGINS`, `VOX_ALLOWED_HOSTS`).
- Request, text-length and concurrent-inference limits; graceful shutdown; `GET /health/ready`.
- Model downloads are pinned to a revision and verified by size and SHA-256.
- The server still has no authentication. Keep it on loopback or put it behind something that has.

### OpenAI-compatible API
- `POST /v1/audio/transcriptions`, `POST /v1/audio/speech`, `GET /v1/models`, `GET /v1/models/{id}`. OpenAI SDKs can use a Vox server as their `base_url` for transcription and speech. Chat completions are not provided.

### Embeddable
- The HTTP/WebSocket server is part of the library: `vox::server::{build_router, serve, run_with_config, ServerState}`.
- `VoxBuilder::build_with_channel` runs the engine without an audio device; `Vox::listen_until` takes your own stop condition.
- `cpal` and Ctrl-C handling are behind the `mic` and `signal` features; the core no longer pulls in tokio's `full` feature set.

### CLI and UI
- `vox tune` measures the installed STT, TTS and Ollama models on a spoken sample and saves the best as the defaults of `vox chat`. `--dry-run` only recommends.
- `vox doctor` explains which models directory is used and which models are missing or corrupt.
- `vox serve --download`, `--language`, `--stt-model`, `--piper-voice`, `--ollama-host`.
- Multilingual Whisper models, Whisper large-v3-turbo and a Turkish Piper voice in the model registry.
- Redesigned web UI that opens on Live Talk.

### Fixes
- Whisper honours the configured language instead of always assuming English.
- Microphone capture resamples from the device's real sample rate; Silero VAD gets the context samples the v5 model expects.
- Speakers are no longer wiped at startup; speaker IDs are not reused after a delete.
- Kokoro reads numbers aloud and no longer truncates long text.
- Qwen3 inference no longer blocks the async runtime.

Full list: [CHANGELOG.md](https://github.com/mrtozner/vox/blob/v0.7.0/CHANGELOG.md).

## Breaking changes

- **`GET /v1/models` returns the OpenAI list shape.** Vox's own model report moved to `GET /v1/vox/models`.
- **The Cargo package is `vox-voice`.** The library crate and the binary are still `vox`, so `use vox::...` and the command line do not change.
- **Remote access is off by default.** The server refuses a non-loopback `--host` without `VOX_ALLOW_REMOTE=1` and rejects origins and hosts that are not allow-listed.
- **Speaker enrollment is opt-in.** Voiceprints are stored and adapted only after consent is recorded.
- **`mic` and `signal` are Cargo features** (on by default). With `default-features = false`, `Vox::builder().build()`, `AudioCapture` and Ctrl-C in `Vox::listen()` need them.
- **tokio features are narrower.** An application that relied on Vox to enable tokio's `full` set must enable what it uses.
- **Minimum Rust version is 1.88.**
- **Platform minimums for the binaries:** glibc 2.39+ on Linux (Ubuntu 24.04, Debian 13, Raspberry Pi OS Trixie), macOS 13.4+, and an x86-64-v3 CPU (AVX2: Intel Haswell / AMD Zen or newer) on x86_64. They come from the ONNX Runtime build Vox links.
- **No Intel macOS binary**; the Homebrew formula, `Dockerfile.static` and the static/cross build scripts were removed because they did not build the current crate.
- Unused `ModelCache`, `StreamingPipeline` and `intelligence` modules were removed.

## Upgrade notes

- Clients of the old `/v1/models` report: switch to `/v1/vox/models`.
- Cargo dependency:
  ```toml
  vox = { package = "vox-voice", git = "https://github.com/mrtozner/vox", tag = "v0.7.0" }
  ```
- Install from source (not on crates.io yet):
  ```bash
  cargo install --locked --git https://github.com/mrtozner/vox --tag v0.7.0 vox-voice --features dist
  ```
- Serving to other machines: set `VOX_ALLOW_REMOTE=1` and list the allowed `VOX_ALLOWED_HOSTS` / `VOX_ALLOWED_ORIGINS`. There is no authentication.
- Library users with `default-features = false`: add `mic` and/or `signal` if you use the microphone or Ctrl-C handling.
- Models are resolved at run time: `VOX_MODELS_DIR`, then a source checkout's `models/`, then the per-user data directory. Run `vox doctor` if a model is not found, and `vox serve --download` to fetch the defaults.
- Live Talk clients: read `protocol_version` from `ready`, keep the `session_id` to resume a conversation, send `cancel` when the user speaks over playback, and send `playback_done` (with `heard_sentences`) so the server knows what was played.
- Raspberry Pi: use the Linux aarch64 archive on Raspberry Pi OS Trixie (64-bit); see `docs/raspberry_pi.md`. On Bookworm, build from source with your own ONNX Runtime.

## Downloads and verification

Archives: Linux x86_64 and aarch64 (glibc 2.39+), macOS 13.4+ on Apple Silicon, Windows x86_64 (without Piper: espeak-ng does not build with MSVC, so Windows uses Kokoro). x86_64 builds need an AVX2-capable CPU.

Every archive is listed in `SHA256SUMS` and has a build provenance attestation:

```bash
sha256sum --check SHA256SUMS --ignore-missing
gh attestation verify vox-v0.7.0-<target>.tar.gz --repo mrtozner/vox   # .zip on Windows
```
